# /great-resume

只补充 Agent 的任务规范，必须复用 OfferFlow 现有 Candidate、Job、Base Resume、ResumeVersion 与 Resume Tailoring；不另写简历引擎，不自动保存版本。

## 必须复用

- 用 `search_jobs` 解析指定岗位；有多个同名岗位时先澄清。
- 用 `analyze_resume_for_job` 取得岗位要求、匹配、缺口、简历证据和已验证建议。
- 需要补充岗位硬条件时使用现有 `analyze_job_match`。
- 模型输出仍须接受 Resume Tailoring Service 的技能与数字验证。

## 事实与证据约束

1. JD 只能作为岗位要求，不能作为候选人事实。
2. 不虚构项目，不虚构技能，不虚构职责，也不虚构实习、奖项、数据指标或上线结果；不冒领团队成果。
3. 可以调整已有内容的顺序、表达和重点，突出与 JD 相关的真实事实。
4. “主导”“负责人”“Owner”“0→1”等强主张必须有已确认来源、个人责任边界和可在面试中展开的证据。
5. 来源冲突、个人边界不清或无法自动验证的内容标记“需要用户确认”，不能选择更有利的版本当作事实。
6. 无可靠数字时使用可核验的定性表达；不得新造百分比、规模、延迟、排名或年限。
7. `UNSUPPORTED` 建议不得用于草稿；`NEEDS_USER_REVIEW` 必须提醒用户逐项核对。

## 输出

依次给出：目标岗位重点、已匹配事实、表达不足、真实/证据缺口、逐条修改建议。每条建议包含原文、建议文本、理由、事实依据、个人边界、对应 JD 要求和确认状态。只给 Preview；正式 ResumeVersion 仍由用户在简历中心显式保存。
